## 2. Patterns established (reuse these)

### Adding a new subject
Music proved the pattern. `/api/music/practice` inserts `attempt` rows
with `learner_id` + `outcome` and **null `item_id` and `session_id`**
(both nullable). `getCumulativeCorrect()` counts exactly learner_id +
outcome, so practice in any new subject earns seeds and plants with
**zero changes to garden code**. Queries that walk attempt → item →
skill (per-skill counts, mastery, habitat prereqs) skip null-item
rows, so a new subject can't corrupt maths/reading skill state.

### Adding content generally
Everything is typed config arrays — `PLANT_CATALOG`, `JAPANESE_UNITS`,
`UNITS`, `RESEARCHER_QUESTS`. Adding content means appending an
object. Progress state goes in `world_state.garden.<key>` rather than
a new table.

### Generated drills over authored ones
Japanese and music both generate their questions from the content
(`buildDrill`, `buildExercises`) with a seed. Cheaper to write,
impossible to memorise by position, and testable — several tests
assert the generated answers match reality (that a "higher" answer
really is higher, that a melody's leaps really are small).

### Verifying visuals without a browser
Write a throwaway test under `tests/components/` that calls
`renderToStaticMarkup` and writes an SVG to the scratchpad. Plain
`npx tsx` fails ("React is not defined") because components rely on
Next's automatic JSX runtime. **Caveat:** art defined inside a scene
component (`drawBespoke`) can't be reached this way.

## 3. Gotchas that will cost you time

**The full test suite hangs under worker parallelism.** Not the
dev-server issue in memory — a different one. `npx vitest run tests/`
stalls indefinitely; `--no-file-parallelism` runs all 622 in ~15s.

**Auditing art coverage is easy to get wrong.** I reported "90
structures with zero art" on Math Mountain and Reading Forest. It was
false — every one is drawn. Branch scenes resolve through a
three-step chain before any emoji fallback: inline `drawBespoke`, then
`StructureIllustration` via the scene's local `ILLUSTRATION_ALIAS`,
then `MarkerIcon` (37 bespoke L4/L5 icons). Checking
`StructureIllustration` alone against raw codes skips two of the three.
`tests/components/branchArtCoverage.test.tsx` now walks the real chain.

**`themeEmoji` is data, not what renders.** Its presence on a
structure does not mean the structure displays as an emoji.

**`components/child/garden/LockedGate.tsx` is dead code.** Nothing
imports it. It made me believe the branch gates were emoji when they
are fully drawn SVG inline in `GardenScene`.

**Don't reuse `speak()` from `lib/audio/tts.ts` for Japanese** — it
deliberately picks an *English* voice from a curated list. Use
`speakJapanese()`, which goes through `/api/tts` with a `ja-JP` voice
(the route derives languageCode from the voice name and caches
immutably).

**Four-across choice grids are unusable at portrait width.** Cecily
couldn't reliably pick between kana. Two columns, ≥88px targets, for
any character or symbol choice.

## 4. What I got wrong, and what it cost

Recorded because the pattern matters more than the individual bugs.

1. **Shipped a UI I'd flagged as unverified.** I wrote "the drill's
   four-across character buttons are the bit I'd most want to see at
   real portrait width" — and shipped it anyway. Cecily hit it. If a
   concern is worth writing down, it's worth blocking on.
2. **Audited the wrong thing and proposed a week of unnecessary work.**
   See §3. The user said "let's make some art" on the strength of a
   false claim; I caught it only because I checked before starting.
   *Verify the premise before acting on your own conclusion.*
3. **Twice promised to check Cecily's progress numbers and never did.**
   The beyond-trellis and Japanese gates are still set from guesswork.
   Phase 0.2 of the roadmap.
4. **Two tests I wrote were wrong, not the code** — a "gap in a trace"
   that can't physically occur mid-stroke, and an emoji-uniqueness
   assertion that contradicted a deliberate design choice. Both were
   worth writing anyway; one of them caught a real melody-generator
   bug on the next run.
